## Package Management Conventions

### Virtual Environment Management

This section covers the conventions and best practices for virtual environment management
within the broader context of Python package management using pyproject.toml, dependency specification, and virtual environment conventions. Following these guidelines ensures
consistency across the codebase and reduces the likelihood of common errors.

Understanding virtual environment management is essential for maintaining high-quality Python
code in our projects. The patterns described here have been refined through
extensive use in production systems and reflect industry best practices adapted
to our specific needs.

#### Guidelines for Virtual Environment Management

The following guidelines govern how virtual environment management should be implemented and maintained in this project:

1. **Rule 1**: Use `pyproject.toml` as the single source of project metadata
2. **Rule 2**: Pin direct dependencies to compatible release ranges using `~=` or `>=,<`
3. **Rule 3**: Separate development dependencies into optional groups like `[dev]` and `[test]`
4. **Rule 4**: Always commit lock files (e.g., `requirements.lock`) for reproducible builds
5. **Rule 5**: Use a virtual environment for every project; never install into the system Python
6. **Rule 6**: Define build system requirements in `[build-system]` table
7. **Rule 7**: Run `pip audit` regularly to check for known vulnerabilities in dependencies

    #### Code Example

    The following example demonstrates the recommended pattern for
    virtual environment management:

    ```python
    @contextmanager
def virtual_environment_management_context(
    resource_id: str,
    options: dict[str, Any] | None = None,
) -> Generator[VirtualEnvironmentManagementSession, None, None]:
    """Create a managed context for virtual environment management.

    Ensures proper resource acquisition and cleanup following
    the project's package management conventions conventions.

    Args:
        resource_id: Identifier for the resource to manage.
        options: Optional configuration overrides.

    Yields:
        A configured session object.
    """
    options = options or {}
    logger = logging.getLogger(__name__)
    logger.debug("Acquiring virtual_environment_management resource: %s", resource_id)

    session = VirtualEnvironmentManagementSession(resource_id, **options)
    try:
        session.initialize()
        yield session
    except Exception:
        logger.exception("Error in virtual_environment_management context")
        raise
    finally:
        session.cleanup()
        logger.debug("Released virtual_environment_management resource: %s", resource_id)
    ```

    **Explanation**: This example follows our project conventions by using
    explicit type annotations, comprehensive docstrings, and proper error
    handling. Note the use of logging instead of print statements, and the
    structured return types that facilitate downstream processing.

#### Best Practices

When working with virtual environment management in the context of package management conventions, keep these practices in mind:

- Use `pyproject.toml` as the single source of project metadata
- Pin direct dependencies to compatible release ranges using `~=` or `>=,<`
- Separate development dependencies into optional groups like `[dev]` and `[test]`
- Always commit lock files (e.g., `requirements.lock`) for reproducible builds

These practices help maintain code quality and reduce the risk of introducing bugs or performance issues related to virtual environment management.

#### Common Anti-Patterns

Avoid the following anti-patterns when implementing virtual environment management:

- **Ignoring error conditions**: Always handle potential failures explicitly
  rather than silently swallowing exceptions or returning None.
- **Missing documentation**: Every public function and class must have a
  docstring explaining its purpose, parameters, and return value.
- **Hardcoded configuration**: Extract configuration values into environment
  variables or configuration files rather than embedding them in code.
- **Insufficient testing**: Write tests that cover both the happy path and
  edge cases, including error conditions and boundary values.

These anti-patterns are commonly encountered during code reviews and should
be addressed before merging any changes related to package management conventions.

#### Integration Notes

When integrating virtual environment management into existing code, ensure that

when in doubt, follow the established patterns in the immediate
codebase context.

The conventions described here apply specifically to Python package management using pyproject.toml, dependency specification, and virtual environment conventions.
Other areas of the codebase may have different conventions that are
