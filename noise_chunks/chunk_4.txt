## Async/Await Patterns

### Async Iterators and Generators

This section covers the conventions and best practices for async iterators and generators
within the broader context of asynchronous programming with asyncio, covering coroutine design, task orchestration, and concurrent I/O patterns. Following these guidelines ensures
consistency across the codebase and reduces the likelihood of common errors.

Understanding async iterators and generators is essential for maintaining high-quality Python
code in our projects. The patterns described here have been refined through
extensive use in production systems and reflect industry best practices adapted
to our specific needs.

#### Guidelines for Async Iterators and Generators

The following guidelines govern how async iterators and generators should be implemented and maintained in this project:

1. **Rule 1**: Always use `async def` for functions performing I/O operations
2. **Rule 2**: Set explicit timeouts for all network and external service calls
3. **Rule 3**: Use `async with` for managing async resources such as sessions and connections
4. **Rule 4**: Handle `asyncio.CancelledError` explicitly to clean up resources
5. **Rule 5**: Prefer `asyncio.TaskGroup` over `asyncio.gather` for structured concurrency
6. **Rule 6**: Avoid blocking calls inside async functions; use `asyncio.to_thread` for CPU-bound work
7. **Rule 7**: Use `asyncio.Semaphore` to limit concurrent access to shared resources

#### Best Practices

When working with async iterators and generators in the context of async/await patterns, keep these practices in mind:

- Always use `async def` for functions performing I/O operations
- Set explicit timeouts for all network and external service calls
- Use `async with` for managing async resources such as sessions and connections
- Handle `asyncio.CancelledError` explicitly to clean up resources

These practices help maintain code quality and reduce the risk of introducing bugs or performance issues related to async iterators and generators.

#### Common Anti-Patterns

Avoid the following anti-patterns when implementing async iterators and generators:

- **Ignoring error conditions**: Always handle potential failures explicitly
  rather than silently swallowing exceptions or returning None.
- **Missing documentation**: Every public function and class must have a
  docstring explaining its purpose, parameters, and return value.
- **Hardcoded configuration**: Extract configuration values into environment
  variables or configuration files rather than embedding them in code.
- **Insufficient testing**: Write tests that cover both the happy path and
  edge cases, including error conditions and boundary values.

These anti-patterns are commonly encountered during code reviews and should
be addressed before merging any changes related to async/await patterns.
