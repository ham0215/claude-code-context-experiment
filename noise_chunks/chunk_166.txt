## Deployment Patterns

### Environment-Based Configuration

This section covers the conventions and best practices for environment-based configuration
within the broader context of Python application deployment conventions using Docker, WSGI/ASGI servers, and container orchestration patterns. Following these guidelines ensures
consistency across the codebase and reduces the likelihood of common errors.

Understanding environment-based configuration is essential for maintaining high-quality Python
code in our projects. The patterns described here have been refined through
extensive use in production systems and reflect industry best practices adapted
to our specific needs.

#### Guidelines for Environment-Based Configuration

The following guidelines govern how environment-based configuration should be implemented and maintained in this project:

1. **Rule 1**: Use multi-stage Docker builds to minimize final image size
2. **Rule 2**: Run Python applications as non-root users inside containers
3. **Rule 3**: Set `--workers` based on CPU count: `2 * CPU + 1` for Gunicorn
4. **Rule 4**: Implement `/health` and `/ready` endpoints for orchestrator probes
5. **Rule 5**: Handle SIGTERM gracefully to allow in-flight requests to complete
6. **Rule 6**: Use `.dockerignore` to exclude test files, docs, and development artifacts
7. **Rule 7**: Pin base image versions to specific digests for reproducible builds

#### Code Example

The following example demonstrates the recommended pattern for
environment-based configuration:

```python
class EnvironmentbasedConfigurationHandler:
"""Handle environment-based configuration operations.

Implements the standard patterns for deployment patterns
as defined in our project conventions.
"""

def __init__(self, config: dict[str, Any]) -> None:
    self._config = config
    self._logger = logging.getLogger(__name__)

def process(self, data: Any) -> dict[str, Any]:
    """Process data according to environment-based configuration conventions.

    Args:
        data: Input data to process.

    Returns:
        Processed result dictionary.

    Raises:
        ValueError: If data is invalid.
    """
    self._validate(data)
    result = self._transform(data)
    self._logger.info("Processed %d items", len(result))
    return result

def _validate(self, data: Any) -> None:
    """Validate input data."""
    if not data:
        raise ValueError("Input data must not be empty")

def _transform(self, data: Any) -> dict[str, Any]:
    """Apply transformation logic."""
    return {"status": "processed", "items": data}
```

**Explanation**: This example follows our project conventions by using
explicit type annotations, comprehensive docstrings, and proper error
handling. Note the use of logging instead of print statements, and the
structured return types that facilitate downstream processing.

#### Best Practices

When working with environment-based configuration in the context of deployment patterns, keep these practices in mind:

- Use multi-stage Docker builds to minimize final image size
- Run Python applications as non-root users inside containers
- Set `--workers` based on CPU count: `2 * CPU + 1` for Gunicorn
- Implement `/health` and `/ready` endpoints for orchestrator probes

These practices help maintain code quality and reduce the risk of introducing bugs or performance issues related to environment-based configuration.

#### Common Anti-Patterns

Avoid the following anti-patterns when implementing environment-based configuration:

- **Ignoring error conditions**: Always handle potential failures explicitly
  rather than silently swallowing exceptions or returning None.
- **Missing documentation**: Every public function and class must have a
  docstring explaining its purpose, parameters, and return value.
- **Hardcoded configuration**: Extract configuration values into environment
  variables or configuration files rather than embedding them in code.
- **Insufficient testing**: Write tests that cover both the happy path and
  edge cases, including error conditions and boundary values.

These anti-patterns are commonly encountered during code reviews and should
be addressed before merging any changes related to deployment patterns.

#### Integration Notes

When integrating environment-based configuration into existing code, ensure that
the surrounding code follows the same conventions described in this
section. Consistency is more important than any individual rule, so
when in doubt, follow the established patterns in the immediate
codebase context.

The conventions described here apply specifically to Python application deployment conventions using Docker, WSGI/ASGI servers, and container orchestration patterns.
Other areas of the codebase may have different conventions that are
documented in their respective sections.
