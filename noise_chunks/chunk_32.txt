## Database Connection Management

### Health Check and Retry Patterns

This section covers the conventions and best practices for health check and retry patterns
within the broader context of database connection pooling, lifecycle management, and health checking conventions for Python applications. Following these guidelines ensures
consistency across the codebase and reduces the likelihood of common errors.

Understanding health check and retry patterns is essential for maintaining high-quality Python
code in our projects. The patterns described here have been refined through
extensive use in production systems and reflect industry best practices adapted
to our specific needs.

#### Guidelines for Health Check and Retry Patterns

The following guidelines govern how health check and retry patterns should be implemented and maintained in this project:

1. **Rule 1**: Always use connection pooling in production; never create connections per request
2. **Rule 2**: Set `pool_pre_ping` or equivalent health checks to detect stale connections
3. **Rule 3**: Configure maximum pool size based on expected concurrent load
4. **Rule 4**: Use context managers to ensure connections are returned to the pool
5. **Rule 5**: Implement exponential backoff for connection retry logic
6. **Rule 6**: Store connection strings in environment variables, never in source code
7. **Rule 7**: Monitor connection pool utilization and alert on exhaustion

#### Best Practices

When working with health check and retry patterns in the context of database connection management, keep these practices in mind:

- Always use connection pooling in production; never create connections per request
- Set `pool_pre_ping` or equivalent health checks to detect stale connections
- Configure maximum pool size based on expected concurrent load
- Use context managers to ensure connections are returned to the pool

These practices help maintain code quality and reduce the risk of introducing bugs or performance issues related to health check and retry patterns.

#### Common Anti-Patterns

Avoid the following anti-patterns when implementing health check and retry patterns:

- **Ignoring error conditions**: Always handle potential failures explicitly
  rather than silently swallowing exceptions or returning None.
- **Missing documentation**: Every public function and class must have a
  docstring explaining its purpose, parameters, and return value.
- **Hardcoded configuration**: Extract configuration values into environment
  variables or configuration files rather than embedding them in code.
- **Insufficient testing**: Write tests that cover both the happy path and
  edge cases, including error conditions and boundary values.

These anti-patterns are commonly encountered during code reviews and should
be addressed before merging any changes related to database connection management.

#### Integration Notes

When integrating health check and retry patterns into existing code, ensure that

when in doubt, follow the established patterns in the immediate
codebase context.

The conventions described here apply specifically to database connection pooling, lifecycle management, and health checking conventions for Python applications.
Other areas of the codebase may have different conventions that are
