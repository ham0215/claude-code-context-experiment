## CLI Tool Development

### Command Group Organization

This section covers the conventions and best practices for command group organization
within the broader context of Python command-line interface development using click and typer, including argument parsing, output formatting, and user interaction. Following these guidelines ensures
consistency across the codebase and reduces the likelihood of common errors.

Understanding command group organization is essential for maintaining high-quality Python
code in our projects. The patterns described here have been refined through
extensive use in production systems and reflect industry best practices adapted
to our specific needs.

#### Guidelines for Command Group Organization

The following guidelines govern how command group organization should be implemented and maintained in this project:

1. **Rule 1**: Use `typer` or `click` for CLI applications instead of raw `argparse`
2. **Rule 2**: Group related subcommands under a common parent command
3. **Rule 3**: Use `--verbose` / `--quiet` flags to control output verbosity
4. **Rule 4**: Return appropriate exit codes: 0 for success, 1 for general errors, 2 for usage errors
5. **Rule 5**: Use `rich` for formatted terminal output including tables and progress bars
6. **Rule 6**: Support both interactive and non-interactive (piped) modes
7. **Rule 7**: Provide `--output-format` option supporting `json`, `table`, and `text` formats

    Args:

        raise ValueError("Input data must not be empty")

    """Apply transformation logic."""
    return {"status": "processed", "items": data}

#### Best Practices

When working with command group organization in the context of cli tool development, keep these practices in mind:

- Use `typer` or `click` for CLI applications instead of raw `argparse`
- Group related subcommands under a common parent command
- Use `--verbose` / `--quiet` flags to control output verbosity
- Return appropriate exit codes: 0 for success, 1 for general errors, 2 for usage errors

These practices help maintain code quality and reduce the risk of introducing bugs or performance issues related to command group organization.

#### Common Anti-Patterns

Avoid the following anti-patterns when implementing command group organization:

- **Ignoring error conditions**: Always handle potential failures explicitly
  rather than silently swallowing exceptions or returning None.
- **Missing documentation**: Every public function and class must have a
  docstring explaining its purpose, parameters, and return value.
- **Hardcoded configuration**: Extract configuration values into environment
  variables or configuration files rather than embedding them in code.
- **Insufficient testing**: Write tests that cover both the happy path and
  edge cases, including error conditions and boundary values.

These anti-patterns are commonly encountered during code reviews and should
be addressed before merging any changes related to cli tool development.
