## Dataclasses and attrs

### Slot-Based Dataclass Optimization

This section covers the conventions and best practices for slot-based dataclass optimization
within the broader context of Python dataclass and attrs usage conventions for structured data modeling, immutability, and validation patterns. Following these guidelines ensures
consistency across the codebase and reduces the likelihood of common errors.

Understanding slot-based dataclass optimization is essential for maintaining high-quality Python
code in our projects. The patterns described here have been refined through
extensive use in production systems and reflect industry best practices adapted
to our specific needs.

#### Guidelines for Slot-Based Dataclass Optimization

The following guidelines govern how slot-based dataclass optimization should be implemented and maintained in this project:

1. **Rule 1**: Use `frozen=True` for value objects that should be immutable after creation
2. **Rule 2**: Define default values using `field(default_factory=...)` for mutable defaults
3. **Rule 3**: Use `__post_init__` for derived field computation and validation
4. **Rule 4**: Prefer `slots=True` for memory-efficient dataclasses in Python 3.10+
5. **Rule 5**: Use attrs `@define` decorator for classes requiring complex validation
6. **Rule 6**: Keep dataclass fields ordered: required fields first, then optional with defaults
7. **Rule 7**: Use `asdict()` and `astuple()` for serialization rather than custom methods

    name: str

#### Best Practices

When working with slot-based dataclass optimization in the context of dataclasses and attrs, keep these practices in mind:

- Use `frozen=True` for value objects that should be immutable after creation
- Define default values using `field(default_factory=...)` for mutable defaults
- Use `__post_init__` for derived field computation and validation
- Prefer `slots=True` for memory-efficient dataclasses in Python 3.10+

These practices help maintain code quality and reduce the risk of introducing bugs or performance issues related to slot-based dataclass optimization.

#### Common Anti-Patterns

Avoid the following anti-patterns when implementing slot-based dataclass optimization:

- **Ignoring error conditions**: Always handle potential failures explicitly
  rather than silently swallowing exceptions or returning None.
- **Missing documentation**: Every public function and class must have a
  docstring explaining its purpose, parameters, and return value.
- **Hardcoded configuration**: Extract configuration values into environment
  variables or configuration files rather than embedding them in code.
- **Insufficient testing**: Write tests that cover both the happy path and
  edge cases, including error conditions and boundary values.

These anti-patterns are commonly encountered during code reviews and should
be addressed before merging any changes related to dataclasses and attrs.
